# SOC Alert Triage

## Overview

Security Operations Centres receive large volumes of alerts generated by monitoring tools such as SIEM platforms, endpoint protection systems, and intrusion detection systems.

SOC analysts must quickly review and prioritise these alerts to determine whether they represent genuine security threats.

---

## Understanding Security Alerts

Alerts typically include important details such as:

- affected host
- user account involved
- timestamp of the event
- detection rule triggered

Understanding this context allows analysts to determine whether further investigation is required.

---

## Investigation Process

When triaging alerts, analysts typically follow several steps:

1. Review the alert details
2. Examine related logs
3. Identify any suspicious activity
4. Determine the severity of the event

This structured process ensures that potential threats are not overlooked.

---

## Determining Alert Severity

After reviewing available evidence, analysts classify alerts into categories such as:

- false positive
- low risk activity
- suspicious behaviour
- confirmed security incident

High-severity alerts are escalated to incident response teams for further investigation.

---

## Analyst Takeaway

Alert triage is a core responsibility of SOC analysts. The ability to quickly interpret alerts and identify genuine threats is essential for maintaining the security of an organisation’s systems.
